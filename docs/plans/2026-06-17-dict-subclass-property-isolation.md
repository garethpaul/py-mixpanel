# Dict-Subclass Property Isolation

Status: Planned

## Context

`prepare_properties` accepts `dict` subclasses and calls their virtual `copy()`
method. A subclass can return itself, so synchronous tracking adds the configured
project token and generated timestamp to caller-owned data. The same alias can
also make callbacks receive transport-only token and time fields, violating the
existing caller-property and callback-token isolation contracts.

## Priorities

1. Convert accepted mapping input into an exact built-in dict before any
   normalization or enrichment.
2. Preserve nested asynchronous snapshotting, finite JSON validation, project
   token authority, callback behavior, and valid plain-dict compatibility.
3. Add mutation-sensitive synchronous and asynchronous regressions plus static,
   guidance, changelog, and completed-plan contracts.

## Implementation Units

### U1: Canonicalize the top-level property mapping

Files:

- `mixpanel.py`

Approach:

- Replace virtual `properties.copy()` dispatch with built-in dict
  canonicalization.
- Keep existing type validation, distinct-ID validation and trimming, and the
  asynchronous recursive deepcopy in their current order.
- Do not alter nested values for synchronous tracking; the fix is limited to
  top-level caller and callback isolation.

### U2: Prove sync and async isolation

Files:

- `test_mixpanel.py`
- `scripts/check-baseline.sh`

Approach:

- Add a dict subclass whose `copy()` method returns itself.
- Prove synchronous and asynchronous requests still use the configured token,
  while the original mapping and callback payload exclude token and time.
- Scope static contracts to the new regressions and require canonical built-in
  dict construction before enrichment or worker creation.
