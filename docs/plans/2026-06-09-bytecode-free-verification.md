# Bytecode Free Verification

Status: Completed

## Context

The legacy Python 2 test path imports `mixpanel.py` and can leave local `.pyc`
files behind. Those files are ignored by git, but generated bytecode in the
checkout makes verification noisy and can hide stale local state.

## Objectives

- Remove generated Python bytecode from the repository checkout.
- Keep the Python 2 test target from writing local bytecode.
- Extend the shell baseline check to fail when `.pyc` files or `__pycache__`
  directories exist in the repository tree.
- Document the guard in README, VISION, and CHANGES.

## Work Completed

- Removed generated `mixpanel.pyc` and `test_mixpanel.pyc` files from the local
  checkout.
- Added `PYTHONDONTWRITEBYTECODE=1` to the Makefile test target.
- Set `sys.dont_write_bytecode = True` before importing `mixpanel` in the test
  harness.
- Added `__pycache__/` to `.gitignore`.
- Extended `scripts/check-baseline.sh` to reject local bytecode artifacts.
- Updated top-level documentation for bytecode-free verification.

## Verification

- `PYTHONDONTWRITEBYTECODE=1 python2 -m unittest test_mixpanel`
- `scripts/check-baseline.sh`
- `make lint`
- `make test`
- `make build`
- `make check`
- `find . -name '*.pyc' -o -name '__pycache__'`
- `git diff --check`
